## 1. สรุปสำหรับผู้บริหาร

"ออเดอร์ไว" เป็นระบบสั่งอาหารผ่าน QR ที่ **เน้นความเรียบง่ายและความถูกต้องของเงินเป็นหลัก** รันบนคอมพิวเตอร์เครื่องเดียวในร้าน ไม่ต้องใช้อินเทอร์เน็ต ไม่มีค่าใช้จ่ายรายเดือน

**จุดแข็ง:** ความน่าเชื่อถือของข้อมูลและเงิน อยู่ในระดับที่สูงกว่าระบบขนาดเดียวกันทั่วไปอย่างชัดเจน
- ออเดอร์ที่ระบบตอบว่าสำเร็จไม่หายแม้โปรแกรมถูกบังคับปิด
- เลขใบเสร็จไม่ซ้ำไม่ย้อน
- ปิดบิลด้วยยอดที่ไม่ตรงกับที่ลูกค้าสั่งไม่ได้
- ทุกการแก้ไขที่เกี่ยวกับเงินมีบันทึกที่ตรวจการแก้ไขย้อนหลังได้
- ทุกข้อมาจากบั๊กจริงที่เคยพบระหว่าง QA และมีเทสต์ครอบอยู่

**ข้อจำกัดหลัก:**
- **พึ่งพาเครื่องเดียว:** เครื่องเสีย ระบบหยุดจนกว่าจะกู้คืนบนเครื่องใหม่
- **ฟีเจอร์ POS ยังไม่ครบ:** ยังไม่มีส่วนลด, ยกเลิกทีละรายการ, ย้าย/รวมโต๊ะ, คืนเงิน, ตัวเลือกเสริมที่มีราคา, เปิด/ปิดกะ

**ข้อสรุป:** **พร้อมใช้งานจริงสำหรับร้านอาหารนั่งทานขนาดเล็กถึงกลางร้านเดียว** โดยมีเงื่อนไขว่าต้องตั้งสำรองข้อมูลออกนอกเครื่อง ใช้ UPS และทดลองใช้กับอุปกรณ์จริงของร้าน 1–2 วันก่อนเปิดเต็มรูปแบบ

## 3. ข้อดีโดยละเอียด

### 3.1 สถาปัตยกรรมที่เหมาะกับร้านจริง
- **ทำงานได้โดยไม่มีอินเทอร์เน็ต:** ร้านในไทยเจอเน็ตล่มเป็นประจำ ระบบนี้ใช้แค่ WiFi ภายใน หน้าเว็บไม่โหลดฟอนต์ ไอคอน หรือสคริปต์จากภายนอกเลย
- **ไม่มีค่าใช้จ่ายแฝง:** ไม่มีค่าบริการรายเดือนหรือค่าธรรมเนียมต่อออเดอร์ ไม่ผูกกับผู้ให้บริการใด
- **ดูแลง่าย:** ไม่มีฐานข้อมูลที่ต้องดูแล ไม่มี `npm install` ซึ่งมักพังเมื่อเวลาผ่านไป ข้อมูลเป็นไฟล์ JSON อ่านได้ สำรองไฟล์เดียวมีครบทุกอย่าง

### 3.2 ความถูกต้องของเงิน (ด้านที่แข็งที่สุด)
| กลไก | ป้องกันอะไร |
|---|---|
| ราคาคิดที่เซิร์ฟเวอร์ ลูกค้าส่งแค่รหัสเมนู | ลูกค้าแก้ราคาจากมือถือ |
| ปิดบิลต้องส่งยอดที่จำไว้ตอนกดครั้งแรก | ลูกค้าสั่งเพิ่มระหว่างคิดเงิน แล้วยอดที่รับกับยอดที่บันทึกไม่ตรงกัน (เคยเกิด: รับ 132 บันทึก 220) |
| ลูกค้าส่งยอดที่เห็น ถ้าราคาเปลี่ยนตอบ 409 | คิดเงินลูกค้าต่างจากที่เห็นบนจอ |
| เลขบิลไม่ย้อนแม้กู้คืนไฟล์สำรองเก่า | ใบเสร็จเลขซ้ำ |
| `reqId` กันสั่งซ้ำ เก็บคู่กับตะกร้า | กดสั่งซ้ำตอนเน็ตสะดุด / รีเฟรชแล้วกดใหม่ |
| ยกเลิกต้องมีเหตุผล ครัวทำแล้วต้อง PIN เจ้าของ (ช่อง PIN นับรวมเพดานเดารหัสทุกเครื่อง) | พนักงานยกเลิกออเดอร์ที่ลูกค้าจ่ายเงินสดแล้วเก็บเงินเอง หรือเดา PIN เจ้าของผ่านช่องอนุมัติ |
| Audit log + hash chain + สำเนาไป BACKUP_DIR | แก้หรือลบประวัติเพื่อปิดบัง |

### 3.3 ความทนทานของข้อมูล
- **บันทึกก่อนตอบ:** เขียนลงดิสก์ก่อนตอบว่าสำเร็จ ทดสอบด้วยการบังคับปิดโปรแกรม (kill -9) 20 รอบระหว่างออเดอร์เข้า ได้ออเดอร์ 1,321 รายการและบิล 147 บิลที่ตอบสำเร็จ ไม่หายเลย
- **ไฟล์หลักเสีย:** ถ้า data.json อ่านไม่ได้ ระบบกู้จาก .bak เอง ถ้าเสียทั้งคู่ระบบหยุด ไม่เริ่มใหม่ด้วยข้อมูลว่าง ซึ่งจะทำให้ QR ทั้งร้านใช้ไม่ได้
- **ไฟล์ถูกล็อก:** ถ้าแอนตี้ไวรัสหรือโปรแกรม sync ล็อกไฟล์ ระบบลองบันทึกใหม่เองโดยไม่ทำให้ลูกค้าค้าง และขึ้นป้ายเตือนบนหน้าพนักงาน
- **กู้คืนปลอดภัย:** กู้คืนแบบเตรียมให้เสร็จก่อนแล้วค่อยสลับ และสำรองข้อมูลปัจจุบันไว้ก่อนเสมอ
- **เปิดซ้อนไม่ได้:** ระบบไม่ยอมให้เปิดโปรแกรมสองหน้าต่างบนข้อมูลเดียวกัน

### 3.4 ประสบการณ์ผู้ใช้
- **หน้าลูกค้า:** หน้าตาแบบแอปสมัยใหม่ การ์ดรูปใหญ่ หน้ารายละเอียดเต็มจอ ปุ่มย้อนกลับของมือถือทำงานถูกต้อง หมายเหตุแยกจาน ใช้ได้ตั้งแต่จอ 320 px ถึงแท็บเล็ต
- **หน้าพนักงาน:**
  - บนจอใหญ่มีแถบเมนูซ้าย
  - จอครัวตัวใหญ่อ่านได้ไกล
  - สถานะบอกด้วยข้อความ ไม่ได้บอกด้วยสีอย่างเดียว
  - หน้าจอวาดใหม่ทุกครั้งที่มีออเดอร์เข้า แต่ไม่ทับช่องที่กำลังพิมพ์ ไม่ทำโฟกัสหลุด และไม่ทำไฟล์ที่กำลังเลือกหาย
- **แบรนด์ร้าน:** โลโก้และสีปุ่มปรับได้ ระบบคำนวณสีตัวอักษรให้ผ่านเกณฑ์ความคมชัดเอง เจ้าของร้านจึงเลือกสีผิดจนอ่านไม่ออกไม่ได้

### 3.5 คุณภาพทางวิศวกรรม
- **ชุดทดสอบ:** `npm test` 96 เคส ทดสอบบนเบราว์เซอร์จริง 214 ข้อ ตรวจการเข้าถึง 6 ข้อ และสคริปต์ QA เฉพาะทาง (บังคับปิดโปรแกรม, ข้อมูล 1 ปี, ข้ามเที่ยงคืน/ข้ามเดือน, path ภาษาไทยบน Windows, หน่วยความจำ 30 นาที)
- **บั๊กพิสูจน์ได้:** ทุกบั๊กที่แก้มีเทสต์ที่พิสูจน์แล้วว่าล้มกับโค้ดเดิม (บันทึก 37 รายการใน [QA-LOG.md](../QA-LOG.md))
- **กฎกันพัง:** กฎ 55 ข้อใน [AGENTS.md](../AGENTS.md) อธิบายเหตุผลจากบั๊กจริง ช่วยให้คนหรือ AI ที่มาแก้ต่อไม่ทำพังซ้ำ

### 4.1 ความเสี่ยงด้านการดำเนินงาน

| IP เครื่องร้านเปลี่ยน | กลาง | สูง (QR ทั้งร้านเสีย) | ช่อง "ที่อยู่เว็บที่ใส่ใน QR" | ตั้ง DHCP reservation ในเราเตอร์ |

| ใช้ PIN ค่าเริ่มต้น 1234 | กลาง | สูง | ป้ายเตือนบนหน้าจอเจ้าของ | เปลี่ยนตั้งแต่วันแรก |

### 4.2 ฟีเจอร์ที่ยังไม่มี (เรียงตามความสำคัญต่อร้านทั่วไป)
1. **เปิด/ปิดกะและนับลิ้นชัก:** ตอนนี้นับเงินเทียบยอดเงินสดเองได้ แต่ยังไม่มีบันทึกส่วนต่าง
2. **ส่วนลด และยกเลิก/คืนเงินบิลที่ปิดแล้ว:** เจ้าของเท่านั้น ต้องมีเหตุผล
3. **ยกเลิกทีละรายการในตั๋ว, ย้าย/รวมโต๊ะ**
4. **ตัวเลือกเสริมที่มีราคา** (เพิ่มไข่ +10, พิเศษ +20) และขนาด
5. **รายงานเลือกช่วงวัน/รายเดือน, ยอดแยกตามพนักงาน**
6. **เมนูภาษาอังกฤษ** สำหรับร้านที่มีนักท่องเที่ยว
7. **ใบกำกับภาษีเต็มรูป, โหมดราคารวม VAT**
8. **สต็อกวัตถุดิบ**
9. **เครื่องพิมพ์ใบสั่งในครัว**

### 4.3 ข้อจำกัดทางเทคนิค
- **รองรับร้านเดียว เครื่องเดียว:** ขยายเป็นหลายสาขาต้องออกแบบใหม่ (ฐานข้อมูล, การซิงก์)
- **หน้าพนักงานโหลดข้อมูลทั้งก้อน:** โหลดใหม่ทุกครั้งที่มีการเปลี่ยนแปลง เหมาะกับไม่เกิน 60 โต๊ะ
- **ไม่มี HTTPS ในวง LAN:** ผลคือ
  - ฟีเจอร์ที่เบราว์เซอร์บังคับ secure context (เช่น กันจอดับบนแท็บเล็ต) ใช้ได้เฉพาะเครื่องร้านเอง
  - คนในวง WiFi เดียวกันดักข้อมูลได้ในทางทฤษฎี ควรแยก WiFi ลูกค้ากับ WiFi ที่เครื่องร้านใช้ ถ้าเราเตอร์รองรับ
- **เปิดให้ลูกค้าใช้เน็ตมือถือ:** ต้องตั้ง Cloudflare Tunnel และควรมีโหมด "พนักงานยืนยันออเดอร์ก่อนเข้าครัว" ซึ่งยังไม่มี

## 6. คำแนะนำ

### ก่อนเปิดใช้จริง (จำเป็น)
1. **PIN:** ตั้ง `STAFF_PIN` ≥ 6 หลัก และให้พนักงานทุกคนมี PIN ของตัวเอง
2. **สำรองข้อมูล:** ตั้ง `BACKUP_DIR` ไป Google Drive for desktop แล้วลองกู้คืนบนเครื่องอื่นหนึ่งครั้ง
3. **เครือข่าย:** ตั้ง IP เครื่องร้านคงที่ก่อนพิมพ์ QR และใช้ UPS
4. **ทดลองใช้:** ทดลองใช้จริง 1–2 วัน
   - มือถือลูกค้าหลายรุ่น (iPhone Safari, Android Chrome)
   - เครื่องพิมพ์ใบเสร็จ
   - จ่าย PromptPay 1 บาท
5. **ใบเสร็จ:** ถ้าร้านจด VAT ให้นักบัญชีตรวจรูปแบบใบเสร็จก่อน

### พัฒนาต่อ (เรียงตามคุ้มค่า)
1. **เปิด/ปิดกะและนับลิ้นชัก:** ปิดช่องโหว่เงินสดที่เหลืออยู่
2. **ส่วนลด และคืนเงินบิลที่ปิดแล้ว:** มีเหตุผลและ audit
3. **ยกเลิกทีละรายการ, ย้าย/รวมโต๊ะ**
4. **ตัวเลือกเสริมที่มีราคา**
5. **รายงานช่วงวัน/รายเดือน/รายพนักงาน**
6. **โหมดพนักงานยืนยันออเดอร์:** ทำก่อนเปิดให้ลูกค้าสั่งผ่านอินเทอร์เน็ต
7. **fsync และหน้าสุขภาพระบบ:** ดิสก์ สำรองล่าสุด ข้อผิดพลาด

## 7. คำตัดสิน

| เกณฑ์ | ผล |
|---|---|
| ร้านอาหารนั่งทานร้านเดียว 5–40 โต๊ะ | ✅ **แนะนำ** (ทำตามข้อ "ก่อนเปิดใช้จริง") |
| ร้านขนาดกลางที่ใช้ส่วนลด/ย้ายโต๊ะบ่อย | ⚠️ ใช้ได้ แต่ต้องจัดการบางเรื่องนอกระบบจนกว่าจะมีฟีเจอร์ |
| ร้านที่จด VAT ต้องออกใบกำกับภาษี | ⚠️ ต้องให้นักบัญชีตรวจก่อน |
| หลายสาขา / เดลิเวอรี / สต็อก / สมาชิก | ❌ ยังไม่เหมาะ |
