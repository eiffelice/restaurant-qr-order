## ภาพรวม

One-stop รวม 3 งานไว้ในเครื่องเดียว ไม่ต้องกรอกข้อมูลซ้ำ

1. **ขายหน้าร้าน (POS เดิม)** · ทุกการชำระเงินลงบัญชีและตัดวัตถุดิบให้อัตโนมัติ
2. **ต้นทุนและสต็อก** · รับของ ของเสีย ตรวจนับ สูตร ต้นทุนต่อจาน งบซื้อ
3. **บัญชี** · รายจ่าย/รายรับอื่น งบกำไรขาดทุน เงินคงเหลือ เจ้าหนี้ ภาษีมูลค่าเพิ่ม สมุดรายวัน

ระบบใช้**บัญชีคู่** (ทุกรายการ debit = credit) และ**ห้ามแก้หรือลบสมุดรายวันกับสมุดสต็อก** ถ้าผิดให้ "ยกเลิก" ซึ่งระบบจะลงรายการกลับให้ ร่องรอยเดิมยังอยู่ให้ตรวจย้อนได้
ทำงานได้ตอน Internet ดับเหมือน POS และส่งสมุดรายวันขึ้น Cloud เมื่อกลับมาออนไลน์

## ตั้งค่าก่อนเปิดใช้

1. **วัตถุดิบ:** ชื่อ · หมวดงบ · หน่วยใช้ (g / ml / ชิ้น) · หน่วยซื้อ (kg / แพง / ขวด) · จำนวนหน่วยใช้ต่อหน่วยซื้อ · **Yield** (% ที่ใช้ได้จริงหลังล้าง/แกะ) · ระดับที่ควรมี · จุดสั่งซื้อ
2. **สูตรมาตรฐาน:** ใส่ปริมาณ "สุทธิที่อยู่ในจาน" ระบบหาร Yield ให้เอง เช่น กุ้งในจาน 60 g, Yield 80% → ตัดสต็อก **75 g**
3. **ผู้ขาย:** ชื่อ · เลขผู้เสียภาษี (ถ้ามี) · จำนวนวันเครดิต
4. **งบซื้อรายเดือนแยกหมวด:** ของสด · ของแห้ง · ผัก · อาหารทะเล · เนื้อสัตว์ · เครื่องดื่ม
5. **ยอดยกมา:** นับสต็อกจริงวันเริ่ม + เงินสดในลิ้นชัก + เงินในบัญชีธนาคาร ระบบลงเป็นทุนเจ้าของ (3000)
6. **ค่าตั้งระบบ**

| ค่าตั้ง | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| เป้าต้นทุนอาหาร | 35% | ใช้คำนวณ "ราคาที่ถึงเป้า" และแจ้งเตือน |
| เกณฑ์ราคาขึ้น | 10% | ราคารับของสูงกว่าทุนเฉลี่ยเกินนี้ แจ้งเตือนพร้อมจำนวนเมนูที่กระทบ |
| วงเงินรายจ่ายที่ต้องอนุมัติ | 3,000 บาท | แคชเชียร์บันทึกเกินนี้ รอผู้จัดการ |
| เกณฑ์ของเสียที่ต้องรับทราบ | 500 บาท | ของเสียมูลค่าเกินนี้เข้าคิวผู้จัดการ |
| จด VAT | ใช่ | แยกภาษีขาย / ภาษีซื้อ |

ข้อมูลข้อ 1–6 ตั้งจาก Cloud HQ แล้วส่งลง Hub เป็น config ลงลายเซ็น (`cost_master`) เพื่อให้ทุกสาขาใช้มาตรฐานเดียวกัน ผู้จัดการแก้สูตรที่ร้านได้ ระบบเก็บประวัติทุกครั้ง

## งานประจำสัปดาห์

1. ตรวจนับวัตถุดิบครบทุกรายการ 1 ครั้ง
2. เปิด "ส่วนต่างการใช้" ดูวัตถุดิบที่ใช้จริงเกินสูตรมากสุด 5 อันดับ ถ้าเกิน 5% ให้หาสาเหตุ (ตัดเกินสูตร · ลืมบันทึกของเสีย · ของหาย · สูตรไม่ตรงจริง)
3. ดู "ราคาขึ้น" และ "ราคาที่ถึงเป้า" ใน "สูตร & ต้นทุนต่อจาน" แล้วตัดสินใจ: ปรับสูตร เปลี่ยนผู้ขาย หรือปรับราคา
4. จ่ายเจ้าหนี้ที่ใกล้ครบกำหนดใน "เงินคงเหลือ & เจ้าหนี้"

## งานประจำเดือน

1. บันทึกค่าเช่า ค่าน้ำค่าไฟ ค่าอินเทอร์เน็ต เงินเดือน
2. ตรวจงบกำไรขาดทุน: food cost % (เป้า 30–35%) · prime cost % (วัตถุดิบ + ค่าแรง) · กำไรสุทธิ
3. **Menu Engineering** ใน "สูตร & ต้นทุนต่อจาน"
   - **ดาวเด่น** (ขายดี กำไรต่อจานสูง): รักษาคุณภาพ วางตำแหน่งเด่นในเมนู
   - **ขายดีกำไรน้อย:** ทบทวนสูตรหรือขึ้นราคาเล็กน้อย
   - **กำไรดีขายน้อย:** ดันการขาย แนะนำโดยพนักงาน ทำโปรโมชัน
   - **ควรทบทวน:** พิจารณาตัดออกหรือเปลี่ยนสูตร
4. ส่งออกสมุดรายวันเป็น CSV ให้ผู้ทำบัญชี และดู "ภาษีมูลค่าเพิ่ม" เป็น**ตัวเลขประมาณการ**ก่อนยื่น ภ.พ.30 (ผู้ทำบัญชีต้องตรวจเอกสารภาษีซื้อก่อนยื่นจริง)
5. ตั้งงบซื้อเดือนถัดไปจาก ยอดขายคาดการณ์ × เป้าต้นทุนอาหาร

## สูตรที่ระบบใช้

- **ทุนเฉลี่ยเคลื่อนที่:** ทุนใหม่ = (มูลค่าคงเหลือ + มูลค่ารับเข้า) ÷ (จำนวนคงเหลือ + จำนวนรับเข้า)
- **ต้นทุนต่อจาน** = Σ (ปริมาณในจาน ÷ Yield × ทุนเฉลี่ยต่อหน่วยฐาน)
- **ราคาที่ถึงเป้า** = ต้นทุนต่อจาน ÷ เป้าต้นทุนอาหาร (ก่อน VAT)
- **ต้นทุนวัตถุดิบจริง** = ต้นทุนตามสูตร + ของเสีย + ส่วนต่างจากการตรวจนับ
- **Food cost %** = ต้นทุนวัตถุดิบจริง ÷ ยอดขายก่อน VAT
- **Prime cost %** = (ต้นทุนวัตถุดิบ + ค่าแรง) ÷ ยอดขายก่อน VAT
- **ภาษีที่ต้องชำระ (ประมาณ)** = ภาษีขาย − ภาษีซื้อ ที่มีใบกำกับภาษีเต็มรูป

ต้นทุนใน P&L คิดตาม **"การใช้จริง" ไม่ใช่ "ยอดซื้อ"** ของที่ซื้อแล้วยังไม่ใช้อยู่ในบัญชีวัตถุดิบคงเหลือ (1200)
ระบบตรวจทุกครั้งว่า **มูลค่าสต็อกรวมทุกวัตถุดิบตรงกับบัญชี 1200 ทุกสตางค์**

## ขั้นต่อไป (Roadmap ตามคู่มือ)

1. Lot และวันหมดอายุ ตัดแบบ FEFO และแจ้งเตือนของใกล้หมดอายุ
2. สูตรย่อ / ของเตรียม (น้ำซุป ซอส) ตัดสต็อกตอนเตรียม batch
3. ปิดกะเงินสด: นับเงินจริงเทียบระบบ บันทึกเงินขาด/เกิน
4. ค่าธรรมเนียมบัตรและแพลตฟอร์มเดลิเวอรี คำนวณอัตโนมัติ
5. พยากรณ์ยอดขายรายเมนูเพื่อแนะนำปริมาณสั่งซื้อ
6. หน้าแก้สูตรและงบบน Cloud HQ สำหรับหลายสาขา พร้อมเทียบ food cost ระหว่างสาขา
7. ส่งออกในรูปแบบที่โปรแกรมบัญชีนำเข้าได้ และการปิดงวดบัญชี
