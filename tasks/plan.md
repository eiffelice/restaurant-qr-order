# แผนพัฒนา: จากระบบสั่งอาหารผ่าน QR → POS ร้านอาหารครบวงจร

## ภาพรวม
หัวใจของ POS คือ รับออเดอร์ → ส่งครัว → คิดเงิน → ตัดสต็อก → สรุปยอดขาย ต่อกันโดยไม่ต้องกรอกซ้ำ
"ออเดอร์ไว" มีครึ่งแรกแล้ว (รับออเดอร์ ครัว คิดเงิน สรุปยอดพื้นฐาน) แผนนี้เติมส่วนที่ขาดทีละชิ้นแบบ vertical slice
(เซิร์ฟเวอร์ + หน้าเว็บ + เทสต์ ในงานเดียว) แต่ละงานจบแล้วระบบยังใช้งานได้ และเทสต์ผ่านทั้งหมด

## เทียบกับรายการ POS (ตรวจจากโค้ดจริง 2026-10-14)

| หมวด | มีแล้ว | ขาด |
|---|---|---|
| 1. ขายหน้าร้าน | รับออเดอร์ (QR + พนักงานสั่งแทน), จำนวน, หมายเหตุ (ไม่เผ็ด ไม่ใส่ผัก), ยกเลิกทั้งใบ (เหตุผล + PIN เจ้าของ) | **ยกเลิกทีละรายการ**, ทานที่ร้าน/กลับบ้าน/เดลิเวอรี, ตัวเลือกที่มีราคา (เพิ่มไข่ +10), **ส่วนลด/โปรโมชัน** |
| 2. โต๊ะ | ผังโต๊ะ + สถานะ, เปิด/ปิดโต๊ะ, เพิ่ม/ลบโต๊ะ, โต๊ะที่เรียก/ขอบิล | **ย้ายโต๊ะ, รวมโต๊ะ**, แยกบิล (เอาออกโดยตั้งใจ ดู AGENTS ข้อ 10) |
| 3. ครัว (KDS) | แยกจุดทำ, เวลารอ, ใหม่/กำลังทำ/พร้อมเสิร์ฟ/เสิร์ฟแล้ว, เสียงแจ้งเตือน | **พิมพ์ใบสั่งอาหารครัว** |
| 4. ชำระเงิน | เงินสด + เงินทอน, PromptPay QR (สร้างจากเบอร์/รูปของร้าน), ใบเสร็จ 80 มม. | **บัตร/ช่องทางอื่น, แบ่งจ่ายหลายวิธี, เปิด-ปิดกะ + นับเงินขาดเกิน** |
| 5. สต็อก | ตั้งเมนูหมดเอง | **ทั้งหมด**: วัตถุดิบ หน่วย รับเข้า/เบิก/ปรับ สูตรต่อเมนู ตัดอัตโนมัติ แจ้งใกล้หมด ของเสีย |
| 6. รายงาน | วันนี้ (เงินสด/โอน), 7 วัน, ขายดี 7 วัน, CSV รายเดือน | **รายเดือน/ปี, ขายไม่ดี, แยกตามพนักงาน, ส่วนลด/ยกเลิก, ต้นทุน + กำไรขั้นต้น** |
| อื่นๆ | สิทธิ์ 4 บทบาท + PIN รายคน, audit log ราคา/ยกเลิก, สำรอง/กู้คืน, ทำงานได้เมื่อเน็ตล่ม (WiFi ภายใน) | สมาชิก/แต้ม, จัดซื้อ/ซัพพลายเออร์, หลายสาขา |

## การตัดสินใจหลัก
- **ไม่แตะสูตรเงินและรูปแบบข้อมูลเดิม** ในงานที่ไม่จำเป็น ข้อมูลใหม่เป็นแบบเพิ่ม (additive) บิลเก่าที่ไม่มี field ใหม่ยังอ่านได้ (`normalize()` เติมค่าเริ่มต้น)
- **บิลเก่าใน sales/ ห้ามแก้** รายงานใหม่ต้องอ่านบิลแบบเดิม (`method` อย่างเดียว) ได้
- งานที่เปลี่ยนสูตรเงิน (ส่วนลด) หรือต้องออกแบบร่วมกับเจ้าของร้าน (กลับบ้าน/เดลิเวอรี, สต็อก) **ถามก่อน** ตามที่ตกลงไว้
- ทุกงานเงินใช้แนวเดิม: ตรวจที่เซิร์ฟเวอร์, audit, PIN เจ้าของเมื่อเสียของจริง, optimistic check (`from`/`expectedSub`)

## ลำดับงาน (รายละเอียดใน tasks/todo.md)

### ระยะ 1: ขายได้ครบ (ไม่ต้องรอตัดสินใจ)

5. เปิด-ปิดกะ + นับเงินในลิ้นชัก (ขาด/เกิน)
6. รายงาน: รายเดือน/ปี, ขายไม่ดี, แยกตามพนักงาน, ยกเลิก, ช่องทางรับเงิน

### ระยะ 1 ส่วนที่รอตัดสินใจ
7. ส่วนลด/โปรโมชัน (เปลี่ยนสูตรเงิน)

9. ตัวเลือกที่มีราคา (เพิ่มไข่ +10)

### ระยะ 2: คุมต้นทุน
10. วัตถุดิบ + หน่วย + รับเข้า/เบิก/ปรับ/ของเสีย

12. ตัดสต็อกอัตโนมัติเมื่อขาย + แจ้งใกล้หมด
13. ต้นทุนวัตถุดิบ + กำไรขั้นต้นในรายงาน

## คำตอบจากเจ้าของร้าน (14 ต.ค. 2026)
- ส่วนลด: ลดจากค่าอาหารก่อนค่าบริการและ VAT เจ้าของให้ได้เลย แคชเชียร์ต้องมี PIN เจ้าของ
- กลับบ้าน/เดลิเวอรี: ใช้เลขคิว ราคาเดียวกับหน้าร้าน
- สต็อก: ตัดตอนส่งเข้าครัว ยกเลิกแล้วคืน
- รหัส QR ทุกโต๊ะ: เจ้าของเห็นคนเดียว

## คำถามเดิม
- ส่วนลด: ลดจากค่าอาหารก่อนคิดค่าบริการและ VAT (ที่ร้านทั่วไปใช้) ใช่ไหม ใครให้ส่วนลดได้ ต้อง PIN เจ้าของไหม
- กลับบ้าน/เดลิเวอรี: ใช้เลขคิวแทนเลขโต๊ะได้ไหม เดลิเวอรีต้องมีราคาต่างจากหน้าร้านไหม
- สต็อก: ตัดตอนส่งเข้าครัว หรือตอนปิดบิล (แนะนำ: ตอนส่งเข้าครัว ยกเลิกแล้วคืน)
