# Spec: คืนเงิน / ยกเลิกบิลที่ปิดแล้ว

สถานะ: **อนุมัติแล้ว 15 ต.ค. 2026** (ย้อนหลัง 8 วัน · คืนผ่านช่องทางเดียวที่เลือก · คืนตามรายการเท่านั้น) · branch `feat/storage-refund`

## Objective

ตอนนี้ปิดบิลแล้วแก้ไม่ได้เลย กดรับเงินผิด ลูกค้าขอคืนเงิน หรืออาหารจานหนึ่งมีปัญหา ยอดผิดค้างในรายงาน กะ และ CSV
เพิ่มให้ **เจ้าของร้าน** คืนเงินบิลที่ปิดแล้วได้ ทั้งบิลหรือบางรายการ โดย:

- ต้องใส่เหตุผล และยืนยัน PIN ซ้ำ (เงินออกจากร้าน แบบเดียวกับเรื่องสำคัญอื่น)
- บิลเดิมไม่ถูกแก้หรือลบ เลขบิลเดิมยังอยู่ (ใบเสร็จที่ให้ลูกค้าไปแล้วยังตรงกับระบบ)
- ได้ **ใบคืนเงิน** เลขที่ใหม่ อ้างอิงบิลเดิม พิมพ์ให้ลูกค้าได้
- รายงานวันนี้/เดือน/ปี กะ (เงินในลิ้นชัก) และ CSV เป็น **ยอดสุทธิหลังคืนเงิน** และแยกให้เห็นว่าคืนไปเท่าไร เพราะอะไร ใครทำ

ผู้ใช้: เจ้าของร้าน (แคชเชียร์ทำไม่ได้ ตามที่ตกลง 15 ต.ค. 2026)

## การออกแบบข้อมูล (ข้อที่สำคัญที่สุด อนุมัติก่อนเขียนโค้ด)

ใบคืนเงินเป็นระเบียนใหม่ใน `D.sales` และ `sales/YYYY-MM.jsonl` (append-only แบบเดิม) ตัวเลขเป็นค่าลบ:

```js
{ type: 'refund', no: 1042 /* เลขใหม่จาก nextBill ไม่ซ้ำกับบิลใด */, at, refundOf: 1037 /* เลขบิลเดิม */,
  table, sub: -120, svc: -12, vat: 0, total: -132, disc: 0,
  method: 'cash', payments: [{ method: 'cash', amount: -132 }],
  items: [{ name: 'ผัดกะเพรา', qty: -2, price: 60, cost? }], cogs?: 0,
  reason: 'ลูกค้าแพ้อาหาร', cashier: { id, name } /* คนที่คืนเงิน */ }
```

เหตุผลที่เลือกแบบนี้:
- ทุกที่ที่รวมยอดด้วย `s.total` และ `store.paymentsOf(s)` (สรุปวันนี้ รายงานช่วงเวลา กะ CSV คนรับเงิน) ได้ยอดสุทธิทันทีโดยไม่ต้องเขียนใหม่ เมนูขายดีหักจำนวนจานที่คืน
- ใช้การเขียนไฟล์ ตรวจบิลที่ขาด (`reconcileSales`) fsync และไฟล์สำรองเดิมทั้งหมด เลขที่ไม่ซ้ำเพราะมาจาก `nextBill` ตัวเดียวกัน
- บิลเก่าไม่มี `type` = บิลขายปกติ อ่านได้เหมือนเดิม

ที่ต้องแก้ให้รู้จัก `type: 'refund'`: นับ "จำนวนบิล" และ "เฉลี่ยต่อบิล" (ไม่นับใบคืนเงิน) · `normalize()` ยอมรับค่าลบเฉพาะใบคืนเงิน · ส่วนลด/ต้นทุนในรายงาน · ใบเสร็จ/ใบคืนเงินบนหน้าจอ

## กติกา

1. เจ้าของเท่านั้น (`requireStaff` ไม่อยู่ใน PERM) + `requireFresh` (ใส่ PIN ซ้ำ) + เหตุผลอย่างน้อย 2 ตัวอักษร (เลือกจากรายการหรือพิมพ์)
2. คืนได้เฉพาะบิลที่อยู่ใน `D.sales` (8 วันล่าสุด) บิลเก่ากว่านั้นตอบ 400 ให้ทำนอกระบบ
3. **ทั้งบิล:** ยอดคืน = ยอดที่ยังคืนไม่หมดของบิลนั้นทั้งหมด
4. **บางรายการ:** เลือกเมนูและจำนวน (ไม่เกินจำนวนที่ยังไม่ได้คืน) ยอดคืน = (ราคา × จำนวน) × (ยอดรวมบิล ÷ ค่าอาหารบิล) ปัดสองตำแหน่ง ค่าบริการ VAT และส่วนลดจึงถูกหักตามสัดส่วน
5. ยอดคืนรวมของบิลหนึ่ง (ทุกครั้งรวมกัน) ห้ามเกินยอดรวมของบิล · ส่งยอดที่เห็นตอนเปิดหน้าต่าง (`expected`) ถ้าอีกเครื่องคืนไปก่อนแล้วตอบ 409 (แบบ `expectedSub`)
6. คืนผ่านช่องทางเดียว ค่าเริ่มต้น = ช่องทางของบิลเดิม (บิลแบ่งจ่ายเริ่มที่เงินสด) เจ้าของเปลี่ยนได้ · คืนเป็นเงินสดระหว่างเปิดกะ = เงินที่ควรมีในลิ้นชักลดลง
7. ไม่คืนสต็อกวัตถุดิบ (อาหารทำไปแล้ว) ต้นทุนของจานที่คืนยังนับเป็นต้นทุน (กำไรขั้นต้นลดตามยอดขายที่หายไป)
8. audit `bill.refunded` (`refundOf`, `no`, รายการ ยอด ช่องทาง เหตุผล) บันทึกลงดิสก์ก่อนตอบ 200 (กฎข้อ 18)
9. เลขบิลห้ามย้อน: ใบคืนเงินใช้ `nextBill++` เหมือนบิลขาย

## หน้าจอ

- **สรุปยอด → บิลวันนี้:** บิลขายที่ยังคืนไม่หมดมีปุ่ม "คืนเงิน" (เจ้าของ) ใบคืนเงินแสดงเป็นแถวยอดติดลบ ป้าย "คืนเงิน" และ "ของบิล R…-1037"
- **ดูใบเสร็จย้อนหลัง:** ปุ่ม "คืนเงิน" และบอกว่าบิลนี้คืนไปแล้วเท่าไร
- **หน้าต่าง `#refund-dlg`** (นอกส่วนที่วาดใหม่ กฎข้อ 26): เลือก ทั้งบิล / บางรายการ (จำนวนต่อเมนู) · เหตุผล · ช่องทางคืนเงิน · แสดงยอดคืนก่อนกด · ปุ่มยืนยันสีแดง
- **ใบคืนเงิน:** หัวกระดาษ "ใบคืนเงิน" เลขที่ใหม่ "อ้างอิงใบเสร็จเลขที่ …" รายการ ยอดคืน ช่องทาง เหตุผล พิมพ์ 80 มม. ด้วย `printMode('receipt')` เดิม
- **KPI:** การ์ด "คืนเงิน" (จำนวนครั้ง มูลค่า) ในรายงานวันนี้/เดือน/ปี เมื่อมีการคืน ตาราง "รายการคืนเงิน" (เหตุผล ครั้ง มูลค่า)

## CSV

ใบคืนเงินเป็นแถวของตัวเองยอดติดลบ คอลัมน์ใหม่ **"คืนเงินของบิล"** และ **"เหตุผลคืนเงิน"** อยู่หลัง "ต้นทุนวัตถุดิบ" ก่อน "ชำระโดย" (กฎข้อ 66: "เลขที่" ถึง "รวม" ไม่เลื่อน "ชำระโดย … รับเงินโดย, รายการ" ท้ายสุด) อัปเดตเทสต์ที่ตรึงคอลัมน์

## Project Structure / Code Style

- เซิร์ฟเวอร์: `lib/routes.js` (`POST /api/refund`, สรุปยอด รายงาน กะ CSV), `lib/store.js` (`normalize()` ใบคืนเงิน, ช่วยคำนวณยอดที่คืนแล้วของบิล)
- หน้าเว็บ: `public/staff.html` (หน้าต่าง `#refund-dlg`, บิลวันนี้, ใบคืนเงิน, KPI)
- เทสต์: `test/api.test.js` (describe "คืนเงินบิลที่ปิดแล้ว"), `qa/browser.js` (เคส `refund`)
- แบบโค้ดเดิม: handler ตรวจทุก field ด้วยมือ `throw fail('ข้อความไทย', status)` · `audit(req, action, {...})` · ข้อความ/คอมเมนต์ภาษาไทย

## Testing Strategy

เทสต์ API ก่อนเขียนโค้ด (TDD) ครอบ:
- เจ้าของคืนทั้งบิลเงินสด → ใบคืนเงินเลขใหม่ ยอดติดลบ อยู่ใน sales/ วันนี้ยอดสุทธิ = 0 จำนวนบิลไม่นับใบคืนเงิน กะ: เงินที่ควรมีลดลง
- คืนบางรายการ: ยอดตามสัดส่วนรวมค่าบริการ/ส่วนลด · คืนซ้ำจนเกินจำนวน/ยอด = 400 · `expected` ไม่ตรง = 409
- แคชเชียร์/ครัว/พนักงานเสิร์ฟ = 403 · ไม่ใส่ PIN ซ้ำ = 403 reauth · ไม่มีเหตุผล = 400 · บิลไม่อยู่/เก่ากว่า 8 วัน = 404/400
- CSV: แถวคืนเงินติดลบ คอลัมน์ใหม่ตำแหน่งถูก · รายงานเดือน: ยอดสุทธิ + สรุปคืนเงิน · audit มี `bill.refunded` ไม่มี PIN
- kill -9 หลังตอบ 200 แล้วใบคืนเงินยังอยู่ (ใช้ helper เดิม)
- เบราว์เซอร์: เจ้าของคืนบางรายการจากบิลวันนี้ → เห็นใบคืนเงิน พิมพ์ได้ ยอดสรุปเปลี่ยน · แคชเชียร์ไม่เห็นปุ่ม

## Boundaries

- **ทำเสมอ:** ตรวจที่เซิร์ฟเวอร์ทุกอย่าง · audit · เขียนลงดิสก์ก่อนตอบ · `npm test` + `qa/browser.js all` + `qa/a11y.js` ผ่านก่อน commit
- **ถามก่อน:** เปลี่ยนสูตรสัดส่วนยอดคืน · ให้บทบาทอื่นคืนเงินได้ · คืนสต็อก
- **ห้าม:** แก้หรือลบบิลเดิมใน sales/ · ใช้เลขบิลซ้ำ · รับยอดคืนจากหน้าเว็บโดยไม่คำนวณใหม่ที่เซิร์ฟเวอร์ · เก็บ PIN ใน log

## Success Criteria

1. เจ้าของคืนทั้งบิล/บางรายการได้ ใบคืนเงินมีเลขใหม่อ้างอิงบิลเดิม พิมพ์ได้
2. บิลเดิมใน sales/ ไม่เปลี่ยนแม้แต่ไบต์เดียว
3. สรุปวันนี้ รายงานเดือน/ปี กะ และ CSV ตรงกับ (ยอดขาย − ยอดคืน) และแสดงยอดคืนแยก
4. คืนเกินยอด/จำนวน คืนพร้อมกันสองเครื่อง และบทบาทที่ไม่ใช่เจ้าของ ถูกปฏิเสธ
5. `npm test`, `qa/browser.js all`, `qa/a11y.js`, `qa/money.js` ผ่านทั้งหมด

## Open Questions (รอเจ้าของตอบ)

1. **คืนได้ย้อนหลังกี่วัน** ร่างนี้ใช้ 8 วัน (บิลที่อยู่ใน data.json) พอไหม
2. **บิลที่แบ่งจ่ายหลายช่องทาง** คืนผ่านช่องทางเดียวที่เลือก (ค่าเริ่มต้นเงินสด) พอไหม หรือต้องแยกคืนตามสัดส่วนแต่ละช่องทาง
3. **คืนบางส่วนแบบใส่จำนวนเงินเอง** (ไม่ผูกกับรายการ เช่น ชดเชย 50 บาท) ต้องการด้วยไหม ร่างนี้คืนตามรายการเท่านั้น (ชดเชยเป็นเงินใช้ส่วนลดก่อนปิดบิลแทน)
